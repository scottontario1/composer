04

Why .agents is read-only here

This process sees .agents as a separate read-only memory filesystem mounted by the session environment. Its mode is 555, and the supplied filesystem policy grants read access. The ordinary skills/ directory remains writable.

Observed mount boundary

findmnt -T /home/sd/Code2/orch/.agents

TARGET                       FSTYPE  OPTIONS
/home/sd/Code2/orch/.agents    tmpfs   ro,nosuid,nodev,relatime,
                                    mode=555,uid=1002,gid=1002

ro is the mount-level restriction. Mode 555 permits reading and directory traversal without writing. Reading instructions works; creating .agents/skills and symlinks needs write access.

What this establishes

  • Native registration cannot be written to the default target in this session.
  • A chmod cannot make a read-only mount writable.
  • Direct loading of skills/how/SKILL.md remains available.
  • The restriction is environmental, not a requirement of the skill format.

What remains unknown

  • The host administrator's precise reason for this policy.
  • The unsandboxed contents underneath the mount.
  • Which outside session settings could alter the mount.

No chmod, remount, installation, or policy changes were attempted.

In an environment with a writable intended discovery directory, python scripts/skills.py install can register links. Here, use project routing or explicit paths. Another target helps only when it is both permitted and scanned by the host.

The coordinator alone owns the manifest and final report. Each explorer writes its task directory. Allocation snapshots defaults, sets planned state, and starts with no tasks. Later task records and state transitions are coordinator work.

Invalid input and collisions

The checker requires the local two-field frontmatter convention, matching names, nonempty instructions, and existing local Markdown targets. Installation preflights collisions and refuses foreign targets. Missing files, invalid settings, and permission failures return a failing command status.

Partial writes and incomplete work

Registration has no rollback if a later link fails. Allocation also has no rollback if writing the manifest fails after directory creation. The shared contract requires incomplete worker coverage and evidence to remain visible, with one evidence follow-up by default.

Validation limits

Format checks cannot establish provider availability, host discovery, explanation accuracy, visual quality, or execution permissions. Operational evaluation means using a skill on an actual request and examining the produced artifact and evidence.
